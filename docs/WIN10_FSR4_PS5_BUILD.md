# Experimental Veyra 2.2.0: PS5 Remote Play + Windows 10 FSR4 ML

This is a custom AMD build, **not an official Veyra release**. The source starts
at upstream `v2.2.0` (`671f9e963db63cbd7f912caa35c4caa3e0e60f76`).
The Windows 10 compatibility changes are ported from
[MIASock's branch at 1d09ef29](https://github.com/MIASock/Veyra-NRVideo-win10-fsr4ml/tree/1d09ef299c3ff708d41d06197ff0c956b4bb2b04).
The final patch uses GetEnvironmentVariableW rather than deprecated _wgetenv.

## Scope and limitations

- Enables real PS5 Remote Play with pinned Chiaki, all four reviewed upstream
  Veyra patches, and static SDL3 3.4.14 controller support.
- Preserves 2.2.0's PS5 fixes, interface and engine instead of combining a 2.1.9
  executable with 2.2.0 UI files.
- Enables FSR4 and AMF headers, AMD optical flow, Moonlight and Xbox builds.
- Uses **the exact official 2.2.0 AMD package's FFmpeg and libdovi DLLs**.
  Matching headers come from checksum-verified corresponding source archives;
  import libraries are generated from the donor DLL export tables. FFmpeg's
  architecture header is generated by its configure script. Codec code is not
  rebuilt or replaced, preserving the slices256/dav1d/zlib runtime fixes.
- Does not provision NVIDIA Optical Flow, CUDA VFG development headers, XeSS,
  Magewell/DeckLink vendor SDKs, or libass. This is not full official feature
  parity. Existing runtime assets alone do not enable missing compile-time SDKs.
- The AMD FSR DLL alone sees a spoofed Windows 11 build number, and the executable
  opts into Microsoft Agility SDK 1.620.2. Set `VEYRA_NO_WIN11_SHIM=1` for a
  diagnostic run without the version shim. This does not make all Windows 11
  features (for example Live Captions) work on Windows 10.
- CI tests are offline. Successful compilation or initialization does **not**
  validate actual PS5 streaming, controller feedback, or FSR4 inference on a GPU.
- GPU requirements, driver compatibility, fallback and frame quality still need
  validation on the user's RX 9070 XT / Windows 10 machine.

## Running CI

The workflow `.github/workflows/win10-fsr4-ps5.yml` runs on pushes to
`win10-fsr4-ps5-2.2.0`. Enable Actions on your fork first. It also declares
`workflow_dispatch`; GitHub's manual dispatch UI requires the workflow on the
repository's default branch. No change to default branch is required for pushes.

Windows-2022 runners provide MSVC; nothing is installed on the user's PC.
Dependency sources, versions and release archive SHA256 values are pinned in
`scripts/ci/win10-ps5-lock.json`. Dependency compilation uses at most two jobs.
There are no PSN tokens, pairing profiles, signing keys, or user settings in CI.
The workflow uploads a patch artifact only after its build and offline gates pass.
Inspect the run result; this document is not a claim that any run succeeded.

## Installing a successful artifact

1. Start with a **separate clean official Veyra 2.2.0 AMD portable copy**.
   Keep the original installation and its user data intact.
2. Close that copy. Back up its `versions/2.2.0/veyra_qml_ui.exe`, `qml/Veyra`,
   `i18n` and `shaders` before replacing anything.
3. Overlay the artifact's executable, `qml/Veyra`, `i18n`, `shaders` and `agility`
   into `versions/2.2.0/`. The artifact is **not a standalone application**.
   Keep Qt, FFmpeg, libdovi, AMD runtime assets, licensing notices, and the root
   launcher from the official donor. Do not substitute the older experiment's UI.
4. Retain `custom-build-manifest.json`, `dependency-check.json` and this document
   alongside the custom build. The official package manifest describes the donor,
   not the modified executable. Do not falsify its official signature/manifest.
5. First launch with a separate `--data-dir` and verify startup logs. Then test
   PS5 pairing/streaming, SDR/HDR, audio and controller input before enabling FSR4.
   Check logs that ML was actually selected, rather than silently falling back.

Do not configure the official automatic update signing key into this custom
build. An official update would remove the Win10 compatibility modifications.
Keep credentials local. Restore the backed-up application directories and remove
added Agility runtime files to undo the patch.
